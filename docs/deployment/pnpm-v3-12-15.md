# Migration de SeaPilot vers pnpm 10

Date : 8 août 2026
Version : 3.12.15

## Objectif

SeaPilot utilise exclusivement pnpm 10 pour installer et exécuter les dépendances Node.js. La version du gestionnaire est épinglée dans `package.json` et les installations reproductibles s'appuient sur `pnpm-lock.yaml`.

## Commandes de référence

```powershell
corepack enable
pnpm install --frozen-lockfile
pnpm test
pnpm lint
pnpm build
```

Pour ajouter ou mettre à jour une dépendance, utiliser `pnpm add`, `pnpm add --save-dev` ou `pnpm update`, puis valider et committer la modification de `pnpm-lock.yaml`.

## Protections de la chaîne d'approvisionnement

La configuration `pnpm-workspace.yaml` :

- refuse tout script d'installation de dépendance qui n'a pas reçu de décision explicite ;
- refuse explicitement les scripts non nécessaires de `core-js` et `fsevents` ;
- bloque les sources Git ou archives distantes introduites par des dépendances transitives ;
- impose un délai de 24 heures avant de résoudre une nouvelle version publiée.

La migration corrige également les avis de sécurité détectés dans l'ancien arbre npm. Les versions correctives transitives sont épinglées dans `overrides` afin d'éviter qu'une future résolution ne réintroduise une version vulnérable, et React Router est mis à jour vers sa version corrective 7.18.2.

Toute nouvelle dépendance qui déclare un script `preinstall`, `install` ou `postinstall` fait échouer l'installation. Elle doit être examinée, puis explicitement autorisée ou refusée dans `allowBuilds`.

## CI et déploiement

GitHub Actions installe pnpm 10.34.5 avec une action épinglée sur un SHA de commit, active le cache pnpm, puis exécute l'installation figée, les tests et le build.

Vercel utilise :

- installation : détection automatique de pnpm 10 grâce à `pnpm-lock.yaml` ;
- build : `pnpm build` ;
- sortie : `dist`.

L'ancien verrou npm est supprimé afin que `pnpm-lock.yaml` soit l'unique source de vérité des dépendances.
